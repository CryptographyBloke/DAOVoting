## 1. Executive conclusion

The work found and reproduced a concrete privacy leak in T007's legacy lift handling. A malicious incoming BabyJubjub lift can carry order-eight torsion. Reusing it under a secret masking sign exposes that sign in the outgoing representation. This is a representation leak in the T007 construction and invalidates its unrestricted active-adversary privacy argument. It does not establish a break of the original prime-subgroup CGY protocol.

Two repair modes are implemented. Canonical lifts provide a simple deterministic reference. V3 independently rerandomizes every transmitted point by a uniform element of the rational order-eight subgroup. V4 uses the same randomized representation and uncompressed affine message points. Real RTX 4050 arithmetic and all 180 public replay records passed their checks. GPU Pippenger does not accelerate the tested end-to-end workloads on this laptop. Signed-magnitude MSM narrows the largest synthetic MSM gap, but remains approximately CPU speed at 81,920 terms. The strongest result is the security audit and an experimentally validated repair, supported by useful algorithmic engineering. GPU acceleration alone does not yet support a strong systems-paper performance claim.

## 2. T007 security audit

For BabyJubjub over the base field, the rational group has order `8q`, where `q mod 8 = 1`. The rational kernel `K = E(Fp)[8]` has eight points. If an incoming representation is `L = P + T`, with `P` in the prime-order subgroup and `T` in `K`, then an honest sign operation followed by a subgroup mask has outgoing torsion projection `[q]L' = sT`. Since `q = 1 mod 8`, this equals `sT`. A malicious predecessor can choose a point `T` of order greater than two and distinguish `+T` from `-T`.

The regression test uses the actual arkworks BabyJubjub curve, injects a valid order-eight tag into a signed predecessor message, and confirms that the legacy outgoing representation exposes the masking sign. It also checks canonical and randomized modes against the same adversarial input and replays their proofs. The test covers the gate's sign leakage. It does not claim extraction of an arbitrary registered ballot or a break of the original CGY theorem.

This distinguishes the original CGY algebra over prime-subgroup points from T007's encoding extension. The leak arises because the encoding retains torsion while applying a secret-dependent operation. The historical T007 report remains an experiment record and must not be cited as proof that the legacy encoding preserves active-adversary privacy.

## 3. Secure lift constructions

Let `C` be the validated canonical prime-subgroup point and `L` any curve point with `[8]L=C`. There are eight rational lifts, forming a coset of `K`.

**Canonical reference.** Encode as `[8^{-1} mod q]C`. This chooses the unique lift in the prime-order subgroup. The implementation regenerates input lifts from decoded canonical points for each later trustee. This removes incoming torsion dependence and costs extra scalar multiplication.

**Selected randomized format.** Preserve the legacy arithmetic internally, then add an independently sampled uniform `U ∈ K` to every outgoing lift coordinate before commitment and transmission. `K` is enumerated and checked to contain eight distinct on-curve points, each killed by eight, with nonidentity order-eight generator. The new sampler uses an OS-seeded ChaCha20 stream, separate from proof and witness randomness, domain-separated by format, context, trustee and action counter. Three random bits choose one of eight points without modulo bias. The RNG seed is secret and never serialized.

For each fixed canonical point and each base lift, translation by uniform `U` makes the outgoing lift uniform over the same eight-element fiber. Therefore the one-coordinate distribution is independent of the incoming torsion and sign. Independent fresh samples extend this statement to each encoded coordinate. The code realizes this with a pseudorandom generator, so the implementation claim is computational and depends on seed entropy and ChaCha20 pseudorandomness. This is a distribution argument for the new representation, not a complete UC or CGY theorem reproof. Domain separation prevents representation randomness from reusing proof witnesses. Message signatures bind the format version and serialized bytes.

V3 uses the randomized lift with the compact point codec. V4 uses randomized lifts and uncompressed affine points. V1 and V2 encoding behavior remains available for diagnostic replay. The V1 default remains unchanged.

## 4. Certified GPU outsourcing

The certified backend treats the host, input preparation, coefficient generator, CPU checker and CPU fallback as trusted. The CUDA device may return arbitrary output words. It does not receive trustee secrets or proof witnesses in public verification.

Raw limbs are checked against the base-field modulus before field construction. Decoded projective coordinates are checked for curve validity, coordinate consistency and nonzero denominator. Length, framing and missing or extra outputs are checked. Subgroup certificates are checked, scalar inputs at or above `q` are reduced correctly, and device output vectors are immutable before independent random coefficients are sampled. Wrong multiplication, malformed coordinates, invalid limbs, bad certificates and length faults each trigger exact CPU recomputation. A valid alternate lift is accepted only when it decodes to the same canonical point. A nonmember subgroup test remains separate from the all-valid-input fault tests.

For a batch containing at most `2^20` terms, the implemented aggregate check has ideal-fresh-uniform-coefficient false acceptance at most `1/q`, bounded by `2^-128` for the selected coefficient width. For `B` independently checked batches, the union bound is at most `B·2^-128`, plus the coefficient PRG and entropy distinguishing advantage. The actual coefficients come from the operating-system-seeded Rust `ThreadRng`, so the bound is computational under its generator and entropy assumptions, not an unconditional IID statement. The bound covers the checked aggregate equations under the stated host/device fault model. It does not protect a compromised host, DMA, RNG or driver, and does not prove the transcript verifier itself correct.

The `cert:cuda` MSM route intentionally uses trusted CPU Pippenger. It is not evidence of a GPU MSM certificate. V1 certified products, V3/V4 GPU MSM and their respective trust assumptions are reported separately.

## 9. GPU MSM implementation

The original per-term CUDA path and unsigned window-Pippenger baseline remain selectable. The new signed backend recodes subgroup scalar jobs in parallel on the CPU, applies the matching base negation, then uses the existing GPU bucket kernels. The signed path records recoding, transfer, scatter, bucket reduction, combine and conversion timings. The kernel uses linked-list bucket insertion with atomic heads and a thread group per weighted bucket reduction. That design avoids a large dense point-bucket allocation but suffers from collision-chain imbalance under skewed high digits. The RTX 4050 measurements show that implementation overhead still dominates versus the CPU baseline.

## 10. Decode and communication tradeoff

At 81,920 normalized points, three-run codec measurements found compressed encoding at 2,621,440 bytes and uncompressed affine encoding at 5,242,880 bytes. On this already warm process, median per-point decode-and-clear was approximately 0.12 seconds compressed versus approximately 0.006 seconds uncompressed. Encoding was about 0.002–0.003 seconds for both. Every decoded batch matched its canonical point. The result is a local point-codec microbenchmark, not a complete network-message codec benchmark. It excludes signatures, framing and message parsing.

The protocol replay measurements below confirm that V4 can lower complete replay time, at the cost of doubled point payload. A bandwidth model can estimate that extra payload as `2,621,440 / bandwidth` seconds for this point set, but this is analytical and excludes transport overhead. No WAN transfer measurement was made. V4 should therefore be evaluated against the target network and message mix before claiming an end-to-end communication improvement.

## 12. Mathematical guarantees and limitations

The exact membership claim is straightforward: for prime-order `P`, `L=[8^{-1}]P` satisfies `[8]L=P` and belongs to the prime subgroup. For randomized encoding, each fiber is `L+K`. For any two base lifts `L1,L2` in the fiber and uniform `U∈K`, `L1+U` and `L2+U` have identical distributions. Product independence requires independent samples for every protected coordinate and action. ChaCha20 implements a computational approximation to these uniform draws.

The individual batch-equation soundness statement is conditional. If an incorrect residual vector has at least one nonzero component in a prime-order group and coefficients are sampled independently uniformly from a set with at least `2^128` values, a random aggregate is zero with probability at most `2^-128`. Across `B` checks, use `B·2^-128` by the union bound. The implementation uses pseudorandom coefficients, so the distinguishing advantage and seed entropy failure must be added. This is an integrity check for the particular linear equations and supported input domain. It does not replace individual verification in the final correctness benchmark or prove all protocol theorems.

The prior CGY security theorems are unchanged. T008 does not claim a new theorem for active malicious trustees, nor does it establish UC composition or privacy for all applications of cofactor-image representations. V3/V4 GPU MSM consumes only public, validated points and scalar coefficients. The verifier's final acceptance still relies on correctness of the implementation and CPU reference checks in these experiments. V1 certified outsourcing gives probabilistic device-output integrity under the trusted-host model. V3/V4 direct GPU MSM has no such certification guarantee unless its output is checked by the independent CPU verifier.

## 13. Scientific context

Small-coefficient randomized batch verification is established by Bellare, Garay and Rabin. Ristretto and Decaf show that quotient-group encodings can eliminate cofactor ambiguity for specific curves. Work on cofactored EdDSA and pairing-based subgroup checks covers adjacent techniques. GPU cryptographic work such as cuZK studies proving arithmetic and is not a directly comparable public-verifier benchmark. T008's evidence supports a concrete audit and repair for the T007 BabyJubjub lift format plus an implementation comparison. It does not establish a new general-purpose subgroup encoding or a GPU speedup over existing GPU MSM systems.

## 14. Independent paper proposal

A defensible follow-up direction is **“Privacy-Safe Cofactor-Image Encodings for Batched Verification on Edwards Curves.”** The central question is when a verifier-friendly encoding can retain cofactor-image decoding while hiding secret-dependent operations from adversarially chosen torsion representatives.

The current work supports three candidate contributions: (1) a concrete active-adversary counterexample for the T007 masking representation; (2) a canonical reference and randomized fiber encoding with a distribution argument and implementation; (3) a measured CPU/GPU batch-verifier study that includes proof construction, decoding, and transcript replay.

Before submission, the authors should formalize composition across coordinates, gates, adaptive messages and repeated executions, including a simulator for the full transcript. They should prove a versioned encoding and signature binding statement, specify entropy and PRG assumptions, and validate an independent second DLEQ-heavy protocol. Performance work should compare against mature GPU MSM libraries and optimize the skewed bucket distribution. A cryptography venue should be chosen only after the general theorem and novelty comparison are complete. A systems venue could fit after adding independent hardware and network results. This report does not assign a CCF ranking.

## 16. Final research decision

**VALUABLE_ALGORITHMIC_EXTENSION**

The torsion-dependent sign leak is concrete, reproducible on the actual curve, and repaired by a clean randomized-fiber construction with versioned message binding. Real CUDA arithmetic agrees with arkworks and the sanitizer reports no memory errors. However, current GPU MSM is slower than CPU Pippenger at the largest measured batch, and secure GPU MSM does not improve full tally or public replay. The privacy argument needs a complete adaptive transcript proof and the system study needs independent multi-host and broader GPU comparisons before a stronger paper claim is warranted.
