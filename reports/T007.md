## 1. Executive research conclusion

**Classification: `VALUABLE_ALGORITHMIC_EXTENSION`.** The construction is mathematically clean, implemented end to end and measured on CPU. Whether it supports an independent cryptography paper depends on GPU MSM measurements and on generalising to a second protocol.

1. **The obstacle.** Batch verification of CGY proofs is blocked by two things.
   * The proofs are in challenge–response form: commitments are reconstructed and hashed, so nothing aggregates.
   * BabyJubjub has cofactor 8. Randomized aggregation over E(F_p) is unsound for torsion residuals: an order-2 residual survives with probability 1/2 (Proposition 2). Cofactored equations change the accepted set.
2. **Cofactor-image encoding [proven].** Since [8]E(F_p) = G (Lemma 1), the transcript can carry a *lift* Q of each point and every receiver uses [8]Q.
   * **Every decoded point is in the prime-order group,** at the cost of 3 doublings instead of a [q]-multiplication.
   * **Provers obtain lifts for free** by using the bases g/8, h/8, h̃/8 and the scalars k/8 (Lemma 2).
3. **Commitment form, small-exponent batching and pre-weighting [proven].** With every residual in G:
   * one random linear combination per board message (128-bit coefficients, one MSM) verifies all CSZ, ZKP0 and DLEQ relations of that message;
   * the error is ≤ 2^{−128} per check (Theorem 1);
   * the construction is equivalent to the original CGY predicate (Lemma 3, Theorem 4).
   * Pre-weighted decryption shares remove the 5 Lagrange multiplications per gate.
4. **Certified offload for the unchanged v1 format [proven].** An untrusted GPU returns lifted outputs. The CPU checks subgroup membership **exactly** ([8]L = P with L on the curve) and products with one randomized MSM. This closes T006's online integrity gap (2^{−128} per batch), and Theorem 3d shows why the cofactored shortcut cannot work.
5. **Measured on CPU [measured CPU]**, n = 1,024, one paired run (4 vCPUs):

   | Metric | v1 batched (s) | v2 batch (s) | Change |
   |---|---:|---:|---|
   | Public replay | 46.6 | 22.5 | **2.07×** (2.23× vs v1 inline) |
   | Variable-base arithmetic | 35.1 | 6.4 | 5.5× less |
   | Co-located tally | 65.1 | 47.6 | **1.37×** |
   | Trustee proof production | 19.2 | 25.1 | +31 % (cost) |

   * **n = 256 (3 pairs):** replay 12.67 → 6.56 s (**1.93×**); tally 17.73 → 13.36 s (1.33×).
   * **Proof level (CSZ only):** 5.58× faster at 4,096 proofs per batch.
   * **Costs:**
     * proofs are 2.7× larger (CSZ: 208 → 568 B);
     * transcripts are 1.57× larger;
     * point decompression is now the largest remaining cost, 11.2 s of the 22.5 s replay.
   * **Certified offload:** its CPU check costs 18 % (n = 1,024) to 26 % (n = 256) of the device-side work, with zero fallbacks for an honest device.
6. **GPU [projection / awaiting hardware].**
   * The v2 verifier is an MSM workload, the best-optimised GPU primitive.
   * A per-term GPU MSM baseline and certified GPU offload are implemented and validated with the emulated kernel.
   * A GPU Pippenger kernel is designed but not implemented (§13).
   * If the 2.07× CPU replay gain carries over to the i7-14650HX, v2 public verification on the CPU alone (≈ 8.6 s projected from T006's 17.8 s) would already match T006's GPU result (9.6 s). This is a projection to be measured locally.

A subgroup check costs about one variable-base multiplication. The verifier therefore pays about 137 full scalar multiplications per gate; 2.38 M of them at n = 1,024.

* **Prover:** each trustee computes per gate about 7 variable-base and 24 fixed-base multiplications. Its secret-dependent parts are the masking sign, nonces, simulated-branch randomness and the share.
* **Batchability in v1:** the reconstructed commitments are inputs to the hash. Each must therefore be computed exactly and separately, so the challenge–response form admits no algebraic batching. Only the *jobs* can be batched (T005/T006), with no reduction in work.

**Research gap.** The two batch-verification theories each assume something CGY on BabyJubjub lacks:

* exact algebraic batching (BGR) assumes a prime-order group;
* the curve practice (Ed25519) uses cofactored equations that change the accepted set.

For a threshold protocol whose proofs are OR-composed Σ-protocols on a cofactor curve, and whose provers can be modified, an **encoding-level** solution suffices: an exact, prime-order batch verifier that needs neither per-point subgroup tests nor a full Decaf/Ristretto layer.

The same algebra (π = [8] has image G) also gives *exact* certificates for outsourced membership tests. That closes the accelerator-integrity gap identified in T006.

## 5. Selected construction and rationale

**Transcript format v2 = B + E + F**, plus **certified offload G** for the unchanged v1 format.

Why B + E + F:

* The batch soundness bound needs every residual in G.
* Lifts make that true *by construction*, at three doublings per received point instead of a full [q]-multiplication.
* Commitment form turns each message's 26 × 5 relations into one MSM.
* Pre-weighting removes the remaining Lagrange multiplications.
* The construction preserves the CGY statements exactly (Lemma 3), needs no new assumption beyond those of the v1 proofs plus Theorem 1, and maps verification onto MSM, the most-optimised GPU primitive.

G is orthogonal. It keeps the existing transcript and makes the T006 GPU path *verifiable*.

## 6. Mathematical definitions

**Setting.**

* E is BabyJubjub over F_p, with p = r_BN254, in arkworks' a = 1 twisted Edwards form.
* #E(F_p) = 8q, with q prime (251 bits).
* G = E(F_p)[q] = ⟨g⟩, where g is Base8.
* h is the committee key and h̃ = HashToG("Conditional gate").
* Enc(m; r) = ([r]g, [m]g + [r]h).
* π := [8] : E(F_p) → E(F_p).

**Definition 1 (lift, cofactor-image encoding).**

* A *lift* of P ∈ G is any Q ∈ E(F_p) with π(Q) = P.
* The v2 wire encoding of P is the compressed encoding of some lift of P.
* Decoding is `Dec(b) = π(Decompress(b))`. Decompression rejects bytes that are not the encoding of a rational point.
* Ciphertexts and proofs are encoded point by point.
* A *canonical* value is π of a lift. All hashing, equality and arithmetic use canonical values.

**Definition 2 (v2 proofs).**

* **Csz2.** For the statement (X₀, Y₀, X₁, Y₁, e) ∈ G⁹, a proof is π₂ = (c_{1,X}, c_{1,Y}, c_{−1,X}, c_{−1,Y} ∈ G², c_{1,e}, c_{−1,e} ∈ G, d₁ ∈ Z_q, a_{1,X}, a_{1,Y}, a_{−1,X}, a_{−1,Y} ∈ Z_q).
  * Set `d = H₂^{csz}(ctx, ℓ, g, h, h̃, e, X₀, Y₀, X₁, Y₁, c, c_e)` and d₋₁ = d − d₁.
  * For σ ∈ {1, −1}, let D_X^σ = X₁ − σX₀ and D_Y^σ = Y₁ − σY₀. The relations, each "= 𝒪", are:

  ```
  [a_{σ,X}]g  − [d_σ]D_X^σ.a − c_{σ,X}.a      [a_{σ,X}]h  − [d_σ]D_X^σ.b − c_{σ,X}.b
  [a_{σ,Y}]g  − [d_σ]D_Y^σ.a − c_{σ,Y}.a      [a_{σ,Y}]h  − [d_σ]D_Y^σ.b − c_{σ,Y}.b
  [a_{σ,X}]h̃ − [d_σ]e       − c_{σ,e}
  ```

  That is 10 relations. Additionally, X₁.a ≠ 𝒪 (CGY Alg. 10, line 1).
* **Zkp02.** Statement A_k ∈ G² (k = 1, 2, or 1 for the release); proof (E_k ∈ G², z_k). Set d = H₂^{zkp0}(ctx, ℓ, A, E). The relations are `[z_k]g − [d]A_k.a − E_k.a` and `[z_k]h − [d]A_k.b − E_k.b`.
* **Dleq2 (pre-weighted share).**
  * Statement: (W_i = [λ_i]h_i, u, w) with u = Y′.a; proof (E₁, E₂, z).
  * Set d = H₂^{dleq}(ctx, ℓ, g, W_i, u, w, E₁, E₂).
  * Relations: `[z]g − [d]W_i − E₁` and `[z]u − [d]w − E₂`.
  * The honest share is w = [λ_i s_i]u, so the opened value is M = Y′.b − Σ_i w_i with no Lagrange multiplications. This requires the fixed decryption set q_dec = a = 5.
* **Domains.** Every H₂ is SHA-256 read big-endian mod q, with v2 domain strings (`wod/v2/…`). ctx binds the setup and sealed board. ℓ = slot·2⁸ + trustee binds the gate and the trustee. The signed message binds the sender and counter.

**Definition 3 (batch verifier).**

* For a message with relation list (R_j)_{j ≤ m}, write each relation as R_j = Σ_b [s_{j,b}]B_b + Σ_i [t_{j,i}]P_i. The B_b are fixed bases in {g, h, h̃, W_from}; the P_i are canonical points.
* The verifier draws independent ρ_j ← [0, 2^λ) with λ = 128, after the message is fixed.
* It accepts iff `Σ_b [Σ_j ρ_j s_{j,b}]B_b + MSM((P_i), (Σ_j ρ_j t_{j,i})) = 𝒪`, and all state, ordering and commitment-hash checks pass.
* *Coefficient sources:*
  * `random` (default): ChaCha20 keyed by fresh OS randomness of the verifier.
  * `fs`: ChaCha20 keyed by SHA-256(domain ‖ ctx ‖ sender ‖ counter ‖ message body). Reproducible, random-oracle analysis.
* On rejection the verifier re-checks every relation individually, to report the offending proof.

**Definition 4 (certified offload of `[k]P` jobs).**

* For jobs (P_i, k_i), the untrusted device receives (P_i, k_i/8 mod q), or (P_i, 1/8) when k_i = q (a subgroup job), and returns L_i.
* The CPU accepts iff:
  1. every L_i satisfies the extended curve equations (X² + Y² = Z² + dT², XY = TZ, Z ≠ 0);
  2. [8]L_i = P_i for every subgroup job;
  3. `Σ_i [α_i]([8]L_i) − MSM((P_i), (α_i k_i)) = 𝒪` over the proof jobs, with fresh α_i ← [0, 2^128) drawn after the outputs are received.
* It then returns 𝒪 for each certified subgroup job and [8]L_i otherwise. On any failure it recomputes the whole batch on the CPU.

## 7. Security theorems and proofs

**Lemma 1 (cofactor image).** [8]E(F_p) = G. The map π : E(F_p) → G is surjective with kernel E(F_p)[8], so every P ∈ G has exactly 8 lifts, and Dec maps every decodable string into G. *(Proven.)*

*Proof.*

* #E(F_p) = 8q with gcd(8, q) = 1, so E(F_p) ≅ E(F_p)[8] × E(F_p)[q] (primary decomposition of a finite abelian group).
* Multiplication by 8 annihilates the first factor, whose exponent divides 8.
* It is a bijection on the cyclic group E(F_p)[q] of odd order q.
* Hence the image is E(F_p)[q] = G and the kernel is E(F_p)[8], which has 8 elements. ∎

**Lemma 2 (free lifts).** If B ∈ G and B′ = [8⁻¹ mod q]B, then for every k, [k]B′ is a lift of [k]B. Sums and integer multiples of lifts are lifts of the corresponding sums and multiples, because π is a homomorphism. *(Proven: π([k]B′) = [k][8·8⁻¹ mod q]B = [k]B, since [q]B = 𝒪.)*

Consequently provers compute lifts at the cost of the canonical computation:

* fixed-base work uses tables for g/8, h/8, h̃/8;
* variable-base work multiplies the canonical base by k/8;
* masking reuses the previous masker's transmitted lift.

The only extra prover work is 4 variable-base multiplications per gate, by the first masker.

Honest lifts all lie in G, so the honest lift of P is the unique lift [8⁻¹]P ∈ G. It is a deterministic function of P and adds nothing to the transcript's information.

**Lemma 3 (equivalence with the v1 statement).** Fix a decoded v2 proof and its canonical statement. The individual v2 verifier accepts if and only if the v1 verification algorithm (CGY Alg. 10 / Alg. 5 / Alg. 4 in challenge–response form), run with the v2 hash domain on the projected proof (d₁, H − d₁, a), accepts, and the transmitted commitments equal the commitments that algorithm reconstructs. *(Proven.)*

*Proof (CSZ; ZKP0 and DLEQ are analogous).*

* v1 reconstructs c̃_{σ,·} from (a, d_σ) and the statement, using exactly the left-hand sides of the v2 relations minus the commitment term. The v2 relations hold iff c = c̃.
* If they hold, H(c̃) = H(c) = d = d₁ + d₋₁, so v1 accepts.
* Conversely, if v1 accepts and c = c̃, the v2 relations hold.
* The X₁.a ≠ 𝒪 check is common to both. ∎

**Corollary (inherited properties).** Completeness, special soundness, HVZK, and knowledge soundness under Fiat–Shamir in the random-oracle model carry over unchanged from the v1 (CGY) proofs. *(Supported by the established theorems for Σ-protocols and Fiat–Shamir.)*

* The statement is the same: canonical points in G.
* The v2 transcript is the standard (commitment, challenge, response) form, of which v1's (challenge, response) is the usual compression.
* The simulator outputs the v1-simulated (d, a) together with the then-determined commitments.
* The extractor rewinds on the same random-oracle query, because the hash input is identical.
* Domain separation (`wod/v2/…`) prevents cross-format reuse of challenges.

**Theorem 1 (batch soundness).** Let R₁, …, R_m ∈ G be the residuals of a message's relations, fixed before the coefficients are sampled, and let ρ_j be independent and uniform on [0, 2^λ) with 2^λ < q. If some R_j ≠ 𝒪, then Pr[Σ_j [ρ_j]R_j = 𝒪] ≤ 2^{−λ}. *(Proven; this is the small-exponent test of Bellare, Garay and Rabin for prime-order groups.)*

*Proof.*

* Pick j* with R_{j*} ≠ 𝒪. G is cyclic of prime order q, so R_{j*} generates G.
* Condition on all ρ_j for j ≠ j*. The event becomes [ρ_{j*}]R_{j*} = −C for a fixed C ∈ G, which holds for exactly one residue ρ_{j*} mod q.
* Since 2^λ < q, at most one value in [0, 2^λ) satisfies it. ∎

*Residuals are well defined and lie in G* because every point entering a relation is canonical (Lemma 1) or a fixed generator.

*Repeated and adaptive use.*

* With `random` coefficients, the verifier's randomness is independent of the adversary's messages, which are fixed before sampling. Over B batch checks the probability of accepting any invalid message is at most B·2^{−λ}, by a union bound, even if the adversary chooses messages adaptively from earlier accept/reject outcomes. Each check uses fresh, independent coefficients.
* With `fs` coefficients in the random-oracle model, an adversary that makes Q_H oracle queries to search for a cancelling message wins with probability at most (Q_H + B)·2^{−λ}. Each fresh message digest yields fresh uniform coefficients.
* For λ = 128 both bounds are negligible for any realistic Q_H.

**Proposition 2 (torsion breaks randomized aggregation over E).** If residuals may lie in E(F_p) \ G, the bound fails.

* For R₁ = T₂ (the order-2 point) and all other R_j = 𝒪, Pr[[ρ₁]T₂ = 𝒪] = Pr[ρ₁ even] = 1/2.
* An order-8 residual survives with probability 1/8.
* Two order-2 residuals with independent coefficients cancel with probability 1/2.
* Cofactored aggregation ([8]Σ ρ_j R_j = 𝒪) accepts every torsion residual with probability 1. It therefore enforces only "relation modulo E[8]", a strictly weaker predicate than the v1 one (compare the Ed25519 cofactored versus cofactorless divergence).

*(Proven by the examples; tested in `sigma::tests::cancellation_and_torsion_residuals`.)* This is why v2 confines every input to G **by encoding**, via Lemma 1, rather than by cofactored equations.

**Theorem 3 (certified offload).** Assume the CPU, its randomness and the job list are trusted, and the device is arbitrary. *(Proven.)*

* (a) Accepting a subgroup job implies P ∈ G exactly, with no error.
  * The certificate satisfies the curve equations, so L ∈ E(F_p) and [8]L ∈ G (Lemma 1).
  * Without the on-curve check, the doubling formulas are polynomial maps on all of 𝔸⁴, and an off-curve preimage of a non-member P could exist. The check is necessary.
* (b) If all proof-job bases P_i are in G (this holds in the protocol: they are transcript points that passed subgroup jobs or are linear combinations of such points and fixed generators), then each [8]L_i ∈ G. If some [8]L_i ≠ [k_i]P_i, the aggregate check passes with probability at most 2^{−128}, by Theorem 1 applied to the residuals [8]L_i − [k_i]P_i ∈ G. The α_i are drawn after the device's outputs are fixed.
* (c) Results returned after acceptance equal the exact values [k_i]P_i (respectively 𝒪 for members), and failed checks fall back to exact CPU recomputation. A malicious device can therefore cause at most a slowdown. Its probability of making the protocol use a wrong value is at most 2^{−128} per batch.
* (d) A cofactored aggregate check could not certify subgroup jobs: a device claiming 𝒪 for [q](P + T₂) passes [8](·) = 𝒪. This explains the two-mechanism design.

**Online trustees and public replay.**

* *Online:* certification completes inside `Engine::process`, before `apply` and before the trustee's next `produce`. The T006 integrity gap (an incorrect device result accepted before secret-dependent actions) is closed up to 2^{−128} per batch. It still assumes an honest host OS and driver for the CPU part.
* *Public replay:* the same bound applies to the verifier's verdict.
* The v2 batch verifier itself, whose MSM is not certified, is trusted CPU code by default. A device MSM for v2 has no cheap certificate: checking an MSM costs an MSM. Its integrity is an open problem (§17).

**Theorem 4 (composition with the protocol).** *(Conditional on the stated assumptions.)*

* *Accepted-result correctness* (paper Theorem 1) holds for v2 transcripts with an additional term of B·2^{−128} for B batch checks (random coefficients), or (Q_H + B)·2^{−128} (Fiat–Shamir coefficients), added to the paper's bound.
  * By Lemma 3 every message accepted by the individual v2 verifier is accepted by the (domain-separated) v1 verifier on the same canonical values. By Theorem 1 the batch verifier deviates from the individual verifier only with that probability.
  * Gate outputs are computed from canonical values exactly as in v1. Pre-weighted shares give M = Y′.b − Σ_i [λ_i s_i]u, the same value as Y′.b − Σ_i [λ_i]([s_i]u).
* *Tally privacy* (paper Theorem 2 and Corollary 1, static corruption of at most 4 of 5 trustees) is unaffected.
  * Honest v2 messages are deterministic re-encodings of v1-distributed values: honest lifts are [8⁻¹]P, and commitments are determined by (d, a) and the statement.
  * W_i is public.
  * The v2 simulator is the v1 simulator followed by this deterministic encoding.
  * This is an argument by reduction to the existing proofs, not a new UC proof.
* *Encoding malleability.* Adding torsion to a lift does not change the decoded message, but it changes the bytes. Board messages are signed, so third parties cannot do this. A sender can produce several byte strings for the same message; they cannot change H(T)-bound content without re-signing. Exact-binding claims concern canonical values.

## 8. Cofactor and subgroup analysis

* **Group structure.** #E(F_p) = 8q (q prime, 251 bits), so E(F_p) ≅ E[8](F_p) × G.
* **Torsion.** The rational 8-torsion has 8 points. arkworks' order-2 point (0, −1) is used in the tests.

| Encoding / check | Accepted points | Verifier cost per point | Exact? |
|---|---|---|---|
| v1: decompress + [q]P = 𝒪 | G | decompression (≈ 13 µs) + 1 scalar multiplication (≈ 39–48 µs measured in T005) | exact |
| Koshelev / Pornin test (not implemented) | G | ≈ 1–3 field exponentiations | exact, under curve conditions |
| **v2: decompress, then [8]Q** | every curve point, read as an element of G | decompression + 3 doublings (≈ 0.3 µs) | **exact semantics**: every lift encodes exactly one element of G, and every element has 8 encodings |
| Cofactored equation [8](Σρ_j R_j) = 𝒪 | relations modulo E[8] | MSM | **not** equivalent to v1 (Proposition 2) |
| **Subgroup certificate** (offload): on-curve L, [8]L = P | G | 3 doublings + curve-equation check | exact (Theorem 3a) |

**Torsion cases.** All are covered by tests (`group`, `sigma`, `tally`, `batch` tests).

| Case | Outcome |
|---|---|
| Lift with an order-2 or mixed torsion offset | accepted, canonical value unchanged |
| Order-2 residual in an aggregate over E | survives with probability 1/2 (counterexample) |
| Device certificate claiming 𝒪 for a torsion point | rejected |
| Off-curve device output | rejected |
| Torsion-offset device output | rejected |

## 13. GPU implementation status

| Component | Status |
|---|---|
| `MulBackend::msm` interface | implemented; default CPU Pippenger (arkworks), used by the v2 batch verifier |
| GPU MSM baseline (`cuda`, `emu`, `auto`) | **implemented as per-term device scalar multiplication plus a host sum**, reusing the T005/T006 `bjj_mul` kernel unchanged. Equivalence was tested with the emulated kernel. It is a correctness baseline: it does *not* yet exploit Pippenger amortisation on the device. **Awaiting GPU** |
| Certified offload (`cert:cuda`, `cert:auto:N`) | implemented and tested with honest and faulty CPU "devices" and with the emulated kernel. Device execution **awaiting GPU** |
| GPU Pippenger MSM kernel | **design only** (below); the Stage B research item |
| Subgroup certificates on the GPU | use the existing kernel with scalar 8⁻¹ mod q (no new kernel needed) |

**Proposed GPU MSM design** (for the next Codex task).

* **Window.** Signed-digit Pippenger with c ≈ 12–14 for N = 10⁴–10⁵ points.
* **Coefficient width.** The 128-bit coefficients ρ of commitment terms need only about ⌈128/c⌉ windows. Splitting terms into a 128-bit class and a 253-bit class saves about 40 % of bucket additions.
* **Bucket accumulation.**
  * Sort (bucket, point) pairs per window with a radix sort.
  * Accumulate with a segmented reduction in extended coordinates, reusing `pt_add` from `bjj.cu`.
  * Finish with a per-window running-sum reduction and a host combination of windows.
* **Memory.** Points can be sent once per message in affine form (64 B instead of 128 B).
* **Dispatch.** Keep `auto:N` dispatch: the v2 per-message MSM sizes (§11) are about 155 terms per gate, so n ≥ 256 messages give MSMs of 10⁴–10⁵ terms.

## 15. Independent-paper novelty assessment

* **Established, not ours:**
  * small-exponent batch verification in prime-order groups;
  * commitment-form Σ-proofs;
  * Pippenger MSM;
  * cofactor-clearing practice;
  * Decaf/Ristretto;
  * Koshelev-style membership tests.
* **Our contribution** is combining them for *threshold MPC transcripts on a cofactor curve with exact semantics*:
  1. **Exact prime-order batching without per-point subgroup tests.** The cofactor-image encoding with *free lifts* (Lemma 2) maintained through a multi-party linear dataflow: CGY masking chains reuse each other's lifts. It is proved equivalent to the original predicate (Lemmas 1, 3; Theorems 1, 4). The counterexample (Proposition 2) shows why cofactored aggregation would not be equivalent.
  2. **Exact certificates for outsourced subgroup membership** ([8]L = P with an on-curve L) and randomized certification of outsourced products. A single untrusted accelerator gives a 2^{−128} integrity bound with only cheap CPU work, and we show the cofactored shortcut fails (Theorem 3d).
  3. **A measured architecture shift** from 137 full scalar multiplications per gate to about 155 MSM terms per gate plus doublings, with paired CPU evidence (§11) and a GPU path.
* **Generalisation.** Any protocol with many Σ-proofs on a cofactor curve whose provers can adopt the encoding:
  * threshold ElGamal decryption with DLEQ;
  * verifiable shuffles over Edwards curves (Bayer–Groth style);
  * DKG with Feldman/Pedersen commitments and DLEQ;
  * Helios-style homomorphic tallies (disjunctive 0/1 proofs);
  * MPC with conditional gates or multiplication triples verified publicly.
  * The certificate technique applies to any cofactor curve where #E(F_p) = h·q with gcd(h, q) = 1. It is most useful when a GPU or other untrusted helper does point arithmetic.
* **CCF C** (e.g. HPCC, HiPC, ICA3PP): contributions 1 + 3 with a complete CPU/GPU evaluation (GPU Pippenger) and generalisation to one more protocol (threshold decryption or a shuffle verifier).
* **CCF B** (e.g. ACNS, ESORICS, Euro-Par/IPDPS): additionally needs either
  * a formal composition proof (batched verification inside the UC/SUC proof of the tally) together with the certified-offload model as a general theorem; or
  * a strong systems result: a GPU Pippenger with crossover and integrity overhead across several GPUs and protocols, and a quantitative comparison with Ristretto-style and Koshelev-style alternatives.

## 17. Remaining mathematical and engineering questions

* **GPU MSM integrity in v2.** Certifying a single MSM costs an MSM. Can bucket-level checks give a cheaper certificate, or is device trust or CPU replay inherent? *Open.*
* **Variable decryption sets.** With q_dec < a and variable subsets, pre-weighting requires knowing the set before shares are produced (one extra round), or falling back to weighting in the MSM. *Open, protocol design.*
* **Encoding malleability.** Should v2 canonicalise lifts (for example, require the unique lift in G, checkable by the receiver only through a membership test)? We accept all 8 lifts and bind canonical values. *Design choice, documented.*
* **Fiat–Shamir coefficients.** The (Q_H + B)·2^{−λ} bound is in the ROM. A standard-model argument for deterministic batching is not given. *Conditional.*
* **Formal composition.** No machine-checked or UC re-proof. Theorem 4 argues by reduction to the paper's existing proofs. *Conditional.*
* **Engineering items:**
  * a GPU Pippenger (§13);
  * affine wire encoding for device transfers;
  * double-buffering of message decoding and MSM;
  * deterministic test vectors for the future GPU MSM (only the per-term baseline is covered now).
